# TravelWise Phase 4 验收报告

日期：2026-10-11（Asia/Hong_Kong）

## 交付范围

Phase 4 在现有 Rule、RuleVersion、Promotion、Evidence 和发布边界上增加了无状态决策计算层与正式计算中心：

- `/calculate`：三类计算器入口。
- `/calculate/rates`：普通会员价与多倍积分价比较。
- `/calculate/offers`：最终报价比较和优惠叠加模拟。
- `/calculate/rewards`：积分活动增量回报计算。
- 活动详情页：对有结构化奖励口径的已发布活动提供活动回报计算器跳转；官方核实且非 DEMO 的积分数量才会预填。

## 公式与精度

核心金额使用 bigint 分，积分估值使用 bigint 微元（1 元 = 1,000,000 微元），格式化只发生在 UI 边界。

房价比较实现：

`额外现金 = 多倍积分价 − 普通价`

`额外积分 = 多倍积分方案积分 − 普通方案积分`

`净增量价值 = 额外积分 × 每积分估值 − 额外现金 − 其他成本 − 放弃权益价值`

当额外积分为正时，盈亏平衡积分价值为 `(额外现金 + 其他成本 + 放弃权益价值) / 额外积分`；额外积分为零、负数或未知时不输出临界值。

优惠组合支持百分比、固定金额、满减和积分抵扣，并按用户指定顺序计算。百分比折扣向下取整到分，固定优惠和积分抵扣不超过当前现金。所有已选优惠的两两叠加关系都要是已核实可叠加才会返回“已核实可用”；未知、有条件或禁止关系会阻断，勾选假设后才返回“假设模拟，非已核实可用优惠”。

活动回报以不参加活动为基准：

`增量净价值 = 新增奖励估值 − 新增经济成本 − 参与费用 − 放弃权益价值`

支持固定积分、分档积分和百分比现金返还；支持次数上限、主动领取、已到账/待到账/过期状态；交易积分按单笔取整。

## 规则与资格边界

- `validateRuleApplicability` 只把已发布、官方核实、有官方证据且在有效期内的 RuleVersion 标记为可用。
- 服务端 `resolvePublishedRule` 重新校验规则状态和证据；不接受客户端金额或规则状态作为事实。
- 资格判断返回“符合已知条件”“不符合已知条件”“信息不足”“规则待核实”四类语义，明确“你提供的信息符合已知规则”不等于官方已经确认个人资格。
- 手动输入与数据库已核实参数冲突时返回冲突说明，不静默覆盖。
- Quote 与 ScenarioSnapshot 作为可复制的领域快照类型存在；不建立私人报价写库，也不新增个人历史账本迁移。

## 典型结果

DEC-01：普通价 300 元/450 分，多倍积分价 350 元/2,800 分，积分估值 0.02 元/分。

- 多花现金：50 元。
- 额外积分：2,350 分。
- 额外积分估值：47 元。
- 净增量价值：-3 元。
- 盈亏平衡积分价值：0.0212766 元/分。
- 权益相同假设下显示普通会员价经济价值更高。

## 已知限制

- V1 仍以用户手动输入实际报价、税费、权益和积分估值为准，不抓取实时酒店价格。
- 锦江荟个人账号、自动报名、自动领奖、个人钱包余额和历史收益账本不在本阶段。
- 活动奖励的具体资格仍需用户确认；官方规则核实不代表个人资格已经确认。
- 当前金额范围受输入校验限制为最多 12 位整数、两位小数；积分最多 15 位非负整数，适用于 V1 手动报价场景。
