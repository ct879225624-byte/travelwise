# TravelWise Phase 3 验收报告

日期：2026-10-11（Asia/Hong_Kong）

## 1. 最终页面结构

- `/`：正式首页、当前支持的锦江荟说明、公开活动、攻略入口、分类入口、计算/我的后续入口。
- `/discover`：服务端活动列表、关键词搜索、类别/平台/生命周期/可信度筛选、排序、分页、空结果状态。
- `/discover/[slug]`：活动摘要、奖励口径、资格、时间窗口、操作步骤、限制、规则版本、关联攻略/活动、来源证据和公开修订时间。
- `/guides`：攻略搜索、12 个真实分类导航、已发布攻略列表和空状态。
- `/guides/[slug]`：安全纯文本文章排版、发布时间/更新时间、关联规则、关联活动、来源引用和阅读边界。
- `/calculate`、`/me`：保留清晰的后续功能入口，不生成虚假计算或个人数据。
- `/admin`：保留 Phase 2 独立管理入口、认证和发布边界。

## 2. UI 设计系统与组件

- 使用浅色背景、深蓝绿色品牌色、细边框、克制阴影和统一圆角；页面不依赖未经核实的图片素材。
- `StatusBadge` 独立呈现活动生命周期和信息可信度；活动卡片同时展示平台、奖励口径、时间和更新时间。
- 全局搜索、按钮、筛选表单、卡片、分页、空状态、加载骨架和错误状态均使用语义化 HTML 与统一 focus ring。
- 纯文本攻略按段落渲染，不执行用户输入 HTML/JavaScript。

## 3. 首页与活动详情

- 首页只读取已发布公开 DTO；真实数据稀疏时显示说明性空状态，不制造优惠、积分或排行榜。
- 活动详情明确区分“官方已核实”“进行中/已结束”和“资格尚未确认”；可以同时出现“官方已核实 + 已结束”。
- 未知截止时间显示“未知/状态待确认”，不会推导长期有效；奖励金额保持来源口径，不解释为用户实际节省。
- 活动详情公开规则、真实关联攻略/活动、来源 URL、摘录、来源类型、核实时间和公开版本时间；管理员、审计操作者、修订原因和快照不进入 DTO。

## 4. 搜索、筛选与关联

- `src/shared/browse.ts` 用 Zod 校验 `q/category/platform/lifecycle/verification/sort/page`，非法或过长参数回退到安全默认值。
- PostgreSQL 查询匹配活动标题和摘要，使用生命周期时钟判断、12 条分页限制和服务端排序；只允许 `publication_status = published`。
- 攻略和活动关联来自 `guide_rule_versions`、`guide_promotions`、`promotion_rules` 等显式关系表，不根据标题猜测。
- DEMO 数据源保留明确 DEMO 标签；生产环境不允许 DEMO 数据源。

## 5. 移动端适配

- 已用 Playwright 覆盖 375px、390px 两个手机视口；筛选按钮可触控、标题可换行、无横向溢出。
- 公开导航在窄屏改为底部触控导航，桌面保留顶部主导航和全局搜索。
- 详情页时间与状态信息在窄屏按单列排列；固定底部导航保留安全区域和正文底部空间。

## 7. Phase 1/2 回归

- 认证拒绝、管理员草稿/证据/发布流程、数据库约束、Seed 幂等、来源 URL 校验和现有公开冒烟流程均通过。

- 本轮没有新增数据库迁移，没有删除或覆盖既有业务数据。

## 8. 已知限制

- 当前只支持锦江荟；未接入其他酒店集团、航空里程或实时价格。
- `/calculate` 只保留边界清晰的后续入口，尚未计算现金节省、积分价值或机会成本。
- `/me` 不接入个人登录、余额或任务提醒；没有公开注册。
- 攻略正文当前是安全纯文本，不提供 Markdown/富文本扩展；当前真实攻略量小，未增加独立分页。
- 页面错误边界提示数据库/网络异常，但不显示原始错误细节。
